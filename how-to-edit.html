How to edit the CADRE website

The site is a folder of plain web pages kept on GitHub. To change the site you change a file in that folder and save it back to GitHub; the live site updates about a minute later. This guide shows four ways to do that, from "send Elena a Word document" to "edit the code yourself." Pick the one that fits the change you want to make.

How the site works

There is no content management system to log into. Each page is one file, and GitHub is where the files live.

The website you see at cadre-cu.github.io is published directly from a GitHub repository, which is a shared, version-controlled folder. GitHub keeps every past version of every file, so a mistake can always be undone, and it records who changed what and when. When a file in the main copy of the repository changes, GitHub rebuilds the site automatically. Nobody has to press publish.

That means every editing method below ends the same way: a changed file is saved to the repository, with a short note describing the change. GitHub calls saving a change a commit and sending it to the shared copy a push. If you use the website editor or Claude, those two steps happen for you.

Right now the site is an unlisted draft. Search engines are told not to index it, and it isn't linked from the CU site. Anyone with the address can view it, so it's fine to share with colleagues, but don't post anything that shouldn't be seen outside CADRE yet.

Option 1

Send a Word storyboard.

The lowest-effort path, and the right one when you're rethinking what a page should say rather than tweaking what's there.

  1. Write the page as a sequence of sections

    Use a heading for each section in the order you want it on the page. The focus-area pages follow this order: Opening (two or three sentences), What we think good work in this area requires, Projects, What's new, Selected publications, People, Resources. You can drop sections you don't need or add one.

  2. Give each project a status and a partner

    Under each project heading, put "Active" or "Completed" on the first line, then a short paragraph. Name the partner or funder in the paragraph. If there's a public link (a report, a task library), paste the address.

  3. List publications in APA style

    Full citations, grouped by person if that's how you want them shown. Include a DOI or web address where one exists; it becomes the "Read paper" link.

  4. For people, give a title and one or two sentences

    Photos come from CU Boulder profile pages unless you send a better one. Include the address of each person's CU profile if you have it handy.

  5. Flag anything unconfirmed

    Put open questions in parentheses, such as "(check with Lorrie)." Anything flagged is left off the page until you confirm it.

  6. Send the document to Derek or Elena

    They run it through Claude Code, review the result on the live preview, and share the link back to you for a final look. Turnaround is usually the same day.

Tip.

Write in the voice of the site: short sentences, no jargon that a district leader wouldn't know, and no more than a paragraph per project. The page will be better for it, and the handoff is faster.

Option 2

Ask Claude Code.

Claude Code is Anthropic's tool for working on files with an AI assistant. Once it has a copy of the site folder, editing is a conversation.

  1. Get access to the repository

    Ask Derek to add your GitHub account to the CADRE-CU organization. If you don't have a GitHub account, create a free one at github.com first, using your CU email.

  2. Put a copy of the site on your computer

    Install GitHub Desktop, sign in, choose File, Clone Repository, and pick CADRE-CU/CADRE-CU.github.io. This creates a folder on your computer that stays connected to GitHub. Remember where you put it.

  3. Open that folder in Claude Code

    In the Claude desktop app, go to the Code tab and open the folder you just cloned. Claude can now see every page of the site.

  4. Describe the change

    Say what you want in ordinary language. For example: "On the Accountability page, add a project card for the ESSER expanded learning evaluation, partner Colorado Department of Education, completed 2025, linking to this report," and paste the link. Or: "Replace Kaitlin Nath's bio with the following." Claude edits the file and can show you a preview of the page before anything is saved.

  5. Ask Claude to commit and push

    Say "commit and push this." Claude saves the change to the repository with a short description. The live site updates within a minute or two; reload it to check.

Things Claude already knows about this site.

The card styles, the six focus areas, where photos live, and the rule about bumping the stylesheet version. If you ask for a new page, it will build one that matches the others. If a request would change many pages at once, it will tell you before doing it.

Before you start each session.

Open GitHub Desktop and click "Fetch origin" so your copy has everyone else's latest changes. Claude can also do this if you ask it to "pull the latest changes first."

Option 3

Edit on the GitHub website.

For small changes to text you can already see on a page. Nothing to install; you edit in the browser and GitHub saves and publishes.

  1. Find the page's file

    Go to github.com/CADRE-CU/CADRE-CU.github.io and click the file for the page you want. The file names match the site: the Accountability page is accountability.html, the homepage is index.html. The table at the bottom of this guide lists them all.

  2. Click the pencil icon

    It's at the top right of the file view ("Edit this file"). The file opens in an editor in your browser.

  3. Find your text

    Press Ctrl+F (Cmd+F on a Mac) and search for a distinctive phrase from the sentence you want to change. You'll see the text wrapped in HTML tags such as <p> and </p>. Change only the words between the tags and leave the tags alone.

  4. Check it reads correctly

    Click the "Preview" tab above the editor to see your change rendered. It won't look exactly like the site, but you can confirm the wording and that nothing broke.

  5. Commit the change

    Click the green "Commit changes" button. In the box that appears, write a one-line description such as "Update Ben Shear's title," leave "Commit directly to the main branch" selected, and click Commit changes again. That's the save. The live site updates within a minute or two.

Safe edits and risky ones.

Safe: changing words, dates, names, and web addresses inside existing tags; copying an existing <li>…</li> publication entry and editing the copy. Risky: deleting or adding tags, moving sections, anything involving the stylesheet. If you're unsure, use Option 2 or ask Derek. Every change can be undone, so the worst case is a few minutes of a slightly broken page.

Special characters.

In HTML, write &amp; for an ampersand and use real typographic quotes and apostrophes (’ “ ”), which you can paste from Word. Accented letters and the ʻokina are fine as they are.

Option 4

VS Code and GitHub Desktop.

For anyone who wants to edit HTML directly with a real editor and see the result locally before publishing. Both programs are free.

  1. Install the two programs and clone the repository

    Install Visual Studio Code and GitHub Desktop. In GitHub Desktop, sign in and clone CADRE-CU/CADRE-CU.github.io (File, Clone Repository). This is the same folder Claude Code uses, so the two can share it.

  2. Fetch before you edit

    Each time you sit down, click "Fetch origin" in GitHub Desktop so you start from the latest version. If it says there are changes to pull, click Pull.

  3. Open the folder in VS Code and edit

    File, Open Folder, choose the cloned folder. Open the page you want from the file list on the left. VS Code colors the HTML so text and tags are easy to tell apart.

  4. Preview locally

    Install the free "Live Server" extension in VS Code, then right-click the page and choose "Open with Live Server." The page opens in your browser and refreshes as you save. Video seeking on the CRG page needs a server, which Live Server provides; simply double-clicking the file won't do.

  5. Commit and push

    Switch to GitHub Desktop. Your changed files are listed on the left. Type a one-line summary in the box at the bottom left, click "Commit to main," then click "Push origin" at the top. The site updates within a minute or two.

If GitHub Desktop reports a conflict.

Someone else changed the same lines since you fetched. Don't force anything; ask Derek or paste the message into Claude Code, which can resolve it.

House rules

Conventions that keep the site consistent.

Claude Code follows these automatically. If you edit by hand, they're worth knowing.

After editing the stylesheet, bump the version

Every page links to styles.css?v=20260910o. Browsers cache the stylesheet aggressively, so after any change to styles.css, change that version string on every page (for example to v=20260924a). Otherwise visitors keep seeing the old styles. Most edits never touch the stylesheet; text and card changes live in the page files.

Adding a project card

Copy an existing card block, from <a class="card flat" (or <div class="card flat" if there's no link) to its closing tag, and edit the copy. The first line inside is the meta row: partner on the left, dates or status on the right. Keep descriptions to one paragraph.

Adding a publication

Copy one <li>…</li> entry in the publication list and edit its four parts: year and type, title, authors, venue with a link. Lists run newest first.

Photos and other files

Headshots go in images/team/, square, about 360 pixels on a side, saved as JPEG. Other images go in images/. Keep files small: a page image should be under 500 KB. Source material that isn't part of the site (Word documents, original logo files, raw video) stays out of the repository; the "Supporting files" folder in Dropbox is the place for it.

The six focus areas appear in three places

The homepage grid, the "Where our work lands" ladder, and every page's footer. Renaming an area or adding one means updating all three, plus the hero sentence on the homepage. That's a job for Option 2.

People

Cards are text-first: name, title, a two- or three-sentence bio, and links to the person's CU profile. A small round headshot appears only when we have a photo. New staff without a CU page yet appear by name only.

At launch

Two things must be removed when the site goes public: the line <meta name="robots" content="noindex, nofollow"> near the top of every page, and the file robots.txt. Until then, search engines ignore the site by design.

Glossary

Words you'll run into.

Repository (repo)
The shared folder on GitHub that holds the site. Ours is CADRE-CU/CADRE-CU.github.io.
Clone
Making a copy of the repository on your own computer that stays connected to GitHub.
Commit
Saving a change to the repository along with a one-line note about what changed. Each commit is a permanent snapshot you can return to.
Push
Sending your commits from your computer up to GitHub. Publishing happens automatically after a push.
Pull or fetch
Bringing other people's commits down from GitHub to your copy. Do this before you start editing.
Main
The name of the primary, published version of the files. All edits in this guide go straight to main.
GitHub Pages
GitHub's free hosting, which turns the repository into the website at cadre-cu.github.io.
HTML
The text format web pages are written in. Words wrapped in tags such as <p>. You change the words, not the tags.

Stuck, or not sure which option fits?

Email Derek or Elena with what you'd like changed. A sentence and a link is enough; the change is usually live the same day.
